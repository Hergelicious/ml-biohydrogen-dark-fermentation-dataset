# Harmonised Dark-Fermentation Biohydrogen Dataset and Cross-Study Validation Pipeline

Data and code for *"How much of the reported accuracy of machine-learning models for dark-fermentative hydrogen yield survives study-level validation? Evidence from 224 harmonised observations"* (Hassan, Moustafa & Abdelkader).

Everything reported in the paper is reproduced by `./run_all.sh`, or by executing the individual Python scripts in sequence. The scripts write the underlying analysis tables and execution logs to `results/` as CSV and log files. **No figures are generated by the pipeline** — Figures 1–6 of the main text and Figures S1–S3 of the supplement are drawn from these output tables.

---

## What this repository is for

Machine-learning models of dark-fermentative hydrogen yield are usually trained on yields compiled from published experiments, routinely reporting $R^2$ above $0.9$. This repository contains the dataset and the pipeline needed to evaluate what those performance metrics actually measure.

The central experiment holds the data, features, encoding and hyperparameters fixed, varying only how the test set is drawn:

| Validation protocol | Random Forest | CatBoost |
|---|---|---|
| Dataset duplicated with Gaussian noise, then split at random | +0.65 | +0.63 |
| Original rows split 80/20 at random | +0.44 | +0.44 |
| **Source studies held out entirely** | **−0.17** | **−0.35** |
| Mean predictor, study-grouped | — | −0.18 |

Under study-level holdout, neither ensemble model beats predicting the overall mean. The reason is a property of the data rather than of the algorithm: **71% of the variance in harmonised yield lies *between* studies**, which is precisely the component a grouped holdout removes.

Completing the full 2 × 2 design separates the two shortcuts rather than inferring them. Noise augmentation is worth **+0.214** under row-wise splitting but only **+0.004** under grouping — so the gain comes from separating a synthetic record from its parent, not from information the synthetic records carry.

### The collapse is not a unit artefact

The most obvious objection to the result is that the harmonised target mixes mass bases, so the grouped failure might reflect denominator heterogeneity rather than genuine study effects. Restricting the target to progressively stricter bases makes the collapse **more** severe, not less:

| Target-basis subset | n | Studies | Grouped $R^2$ |
|---|---|---|---|
| All harmonised records | 224 | 82 | −0.17 |
| Excluding COD, dry-biomass and unstated bases | 212 | 80 | −0.02 |
| Excluding the Group C hexose-equivalent convention also | 178 | 74 | −0.15 |
| Native volatile solids only | 101 | 38 | −1.11 |

On the volatile-solids-only subset every one of the forty resamples is negative and the intraclass correlation rises from 0.71 to 0.79. If anything, the mixed-basis analysis reported in the main results is the more conservative of the two.

### What does survive

A negative $R^2$ shows that absolute point prediction fails, not that nothing transfers. Under the same grouped protocol:

- **Within-study rank ordering partially transfers** (median Spearman $\rho$ = +0.29 inside a held-out study), while **pooled rank ordering does not** ($\rho$ = +0.20, interval spanning zero).
- **Tertile classification does not transfer** (accuracy 0.37 against a chance rate of 0.33).
- **Prediction intervals are anticonservative** — nominal 90% intervals achieve 0.70 empirical coverage.
- The error is driven almost entirely by **how far a withheld study's mean sits from the training centroid** ($\rho$ = 0.59).

Note that these resample-level statistics are computed over study-resample combinations that are **not independent** — each study recurs in a mean of 8.3 test partitions across the 40 resamples — so the accompanying p-values are anticonservative and are reported as descriptive summaries of the resampling distribution rather than as hypothesis tests.

## Installation and use

Python 3.11 or newer is required.

```bash
git clone https://github.com/Hergelicious/ml-biohydrogen-dark-fermentation-dataset.git
cd ml-biohydrogen-dark-fermentation-dataset
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
./run_all.sh                                          # or execute scripts sequentially
```

Runtime is approximately 5–10 minutes, dominated by the resampling loops in `02_validation_ladder.py` and `05_robustness.py`. All random seeds are fixed in `common.py`, so repeated runs reproduce the published values exactly.

## The dataset & references

`data/Full_Data_set.csv` — 261 records from 84 published sources (2002–2025). Full citation details, DOI links and publication metadata for all 84 primary sources are compiled in `data/references.csv` and rendered human-readably in `REFERENCES.md`.

| Column | Contents |
| --- | --- |
| `Substrate`, `Microbial Inoculum`, `Reactor / Mode` | As reported by the original source |
| `pH`, `Temp (°C)` | As reported, including ranges and operational tolerances |
| `Original Yield`, `Original Unit` | Value and unit string exactly as published |
| `dm³ H₂/g` | Harmonised yield ($\text{dm}^3\ \text{H}_2\ \text{g}^{-1}$ substrate at STP) |
| `Conversion Calculation & Notes` | Arithmetic used per record |
| `Unit Group` | Group A, B, C, or Excluded |
| `Reference` | Source study key (primary grouping variable matching `references.csv`) |

### Mass basis of the target

The harmonised target is **dm³ H₂ per gram of substrate, not per gram of volatile solids**. Each record inherits its mass basis from whichever convention its source used, and the basis of every record is recoverable from the `Original Unit` column. For chemically defined sugars the substrate-molecule basis is close to a volatile-solids basis, since such substrates are essentially fully volatile; for records on a COD, dry-biomass or unstated basis it is not. The `07_target_basis_sensitivity.py` script tests whether any conclusion depends on this — none does.

### Unit harmonisation

Twenty-six distinct unit conventions appear in the source literature. Three conversion routes are applied, and a fourth class is excluded:

* **Group A** — Volumetric per mass ($\text{mL}$, $\text{cm}^3$, or $\text{L}\ \text{H}_2$ per $\text{g}$ or $\text{kg}\ \text{VS}$): scaled directly to $\text{dm}^3\ \text{H}_2\ \text{g}^{-1}$.
* **Group B** — Molar yields for chemically defined substrates: $Y \times 22.414 / M$, where $22.414\ \text{dm}^3\ \text{mol}^{-1}$ is the molar volume at STP and $M$ is the molar mass of the named substrate.
* **Group C** — Molar yields for chemically undefined substrates (wastewaters, complex mixed wastes): converted on a hexose-equivalent basis ($M = 180.16\ \text{g}\ \text{mol}^{-1}$).
* **Excluded** — Volumetric productivities ($\text{L}\ \text{H}_2\ \text{L}^{-1}\ \text{reactor}$) or rates ($\text{mmol}\ \text{H}_2\ \text{h}^{-1}\ \text{L}^{-1}$), which cannot be made mass-specific without unstated loading metrics.

`01_audit_dataset.py` re-derives every harmonised value from the original yield and conversion notes: **256 of 257 convertible records agree**, with the single discrepancy corrected in the audited file.

### Quality flags

Written by `01_audit_dataset.py` and retained in `data/Full_Data_set_AUDITED.csv`:

| Flag | Records | Meaning |
| --- | --- | --- |
| `flag_arithmetic` | 1 | Harmonised value disagreed with stated conversion by $>2\%$ |
| `flag_unit_suspect` | 1 | Duplicates adjacent record with a factor-1000 discrepancy |
| `flag_per_slurry` | 16 | Yield per volume of slurry, not per mass of volatile solids |
| `flag_review_duplicate` | 12 | Observation already present under primary study |
| `flag_mw_basis` | 1 | Xylose on a $\text{C}_6$ basis while other xylose records use $\text{C}_5$ |
| `flag_above_thauer` | 8 | Yield above $4\ \text{mol}\ \text{H}_2\ \text{mol}^{-1}$ hexose equivalent |
| `flag_exact_duplicate` | 4 | Exact duplicate of an earlier record in same source |
| `flag_pH_derived` / `flag_T_derived` | 15 | Operational parameters parsed from range or text |
| `recommended_for_modelling` | 224 | Passes quality criteria and has usable yield |

**The modelling set contains 224 observations from 82 studies.** 47 studies contribute a single observation; the six largest contribute 38% of all rows.

## Detailed pipeline structure

* `01_audit_dataset.py`: Recomputes unit conversions, audits arithmetic integrity, applies quality flags, and writes the filtered modelling subset (`dataset_modelling_224.csv`).
* `02_validation_ladder.py`: Evaluates performance across the three validation protocols (noise-augmented random split, row-wise split, study-grouped holdout) and the full 2 × 2 factorial of augmentation and partitioning, across multiple model implementations.
* `03_statistics.py`: Calculates intraclass correlation coefficients, evaluates learning curves under grouped holdout, performs random-effects meta-regression, and calculates pooled yields.
* `04_energy_balance.py`: Couples the meta-regression temperature coefficient ($37^\circ\text{C} \rightarrow 55^\circ\text{C}$), estimated on the native volatile-solids subset so that the statistical estimate and the loading share a mass denominator, to a reactor thermal balance to calculate break-even solids loadings.
* `05_robustness.py`: Evaluates sensitivity to alternative algorithms (CatBoost, XGBoost, LightGBM, Ridge), feature encoding schemes, hyperparameter configurations, and high-leverage observations.
* `06_basis_sensitivity.py`: Tests model behaviour and validation ladders across different original unit classifications.
* `07_target_basis_sensitivity.py`: Evaluates whether the grouped performance collapse persists when the dataset is restricted to mathematically strict target mass bases; also writes the tertile-classification and error-vs-centroid analyses.
* `08_what_transfers.py`: Assesses secondary model capabilities under grouped holdout — Spearman rank correlation, prediction-interval calibration, learning-curve slope, and feature-level ICC.

## Minimum standard for compiled-data models

Based on findings from this pipeline:

1. **Explicit conversions**: Record original units for every observation and publish exact conversion arithmetic per row rather than stating a generic methodology.
2. **Grouped holdouts**: Always group by source study (`Reference`) when performing train/test splits, and explicitly report the grouping variable in the methods.
3. **Resampling distributions**: Report evaluation metrics as distributions across repeated resamples rather than relying on a single train/test split.
4. **Baseline comparisons**: Benchmarks must include a grouped mean predictor and a linear baseline. Algorithms that cannot outperform a naive mean predictor under grouped holdout provide no demonstrated predictive power.
5. **Synthetic augmentation restrictions**: Avoid generating synthetic samples via noise addition or row duplication, as this introduces severe data leakage under random splitting.
6. **Reproducible pipelines**: Publish full data, references and code scripts so that validation protocols can be independently audited.

## Scope of the claim

These results come from one compilation with one feature set. They show that **this dataset** does not support cross-study prediction — not that no dark-fermentation dataset could. Grouped cross-validation also estimates performance on studies drawn from the same literature population; it is not prospective validation, and no independent dataset generated by new experiments is held here. Establishing how widespread the effect is would require applying the same protocol to other compilations in this literature, which the released pipeline is designed to make straightforward.
